The control

Most API breaches are authorisation bugs, not broken cryptography.
The attacker is usually a legitimate, logged-in user changing an id, adding a field, or calling an endpoint nobody linked to.
Authentication asks who you are. Authorisation asks whether this particular user may touch this particular object, and it has to be checked on every request rather than assumed from the interface.
Roadmap: check ownership per object, never trust client-supplied fields, gate every function by role, bound consumption, and know which APIs you actually have.
Pairs with API Key vs JWT vs OAuth 2.0 for proving identity, HTTPS and TLS for the channel, and DevSecOps and GitOps for catching these before release.
