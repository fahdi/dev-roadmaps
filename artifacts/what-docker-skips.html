Containers: What Docker Actually Skips

A container is not a small virtual machine. It is an ordinary process on a kernel that is already running, with two sets of switches flipped. Turn them off below and watch it become an ordinary process again.

Memory-bound ceiling only, counting roughly 2 GB of guest OS per VM against roughly 96 MB of process overhead per container. Real density lands lower, because CPU, file descriptors and PID limits usually bind before memory does. The ratio is the point, not the absolute number.

Nothing boots, because there is nothing to boot. There is one kernel and it was already running.
A VM is fast at the things it is asked to do; it is just asked to do far more.
That is also the trade: the isolation you get is enforced by a kernel you share, not by a hypervisor between you and the hardware.
Roadmap: know which boundary you are standing on. Namespaces and cgroups are kernel features, not a virtual machine.
