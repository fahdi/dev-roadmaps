Developer Roadmap

API Key vs JWT vs OAuth 2.0

Three different problems, three different tools. They get compared as if you choose one, but a single product usually runs all three at once for different hops.

API Key

Application to application No user context at all
Use when One service needs to call another and there is no human in the request.
Typical uses
  • Calling a model provider's API
  • Backend calling a third-party service
  • Scheduled jobs and cron tasks
  • Internal service to service calls
Watch for A leaked key is full access with no user to trace it back to. Rotate them and keep them out of client code.

JWT

User to your application The user is already authenticated
Use when A user has logged in and your app needs to identify and authorise them on every request.
Typical uses
  • Logged-in web and mobile sessions
  • Per-user access in a dashboard
  • Role and permission checks
  • Internal admin portals
Watch for Self-contained means it stays valid until it expires. Revoking early needs a deny list or short lifetimes plus refresh.

OAuth 2.0

User to third party Delegated access, on their behalf
Use when Your app needs permission to reach another service as the user, without ever seeing their password.
Typical uses
  • Sign in with an existing provider
  • Connecting a workspace or mailbox
  • An agent reading a user's documents
  • Enterprise single sign-on
Watch for Scopes are the whole security model. Ask for the narrowest set, because users see exactly what you requested.

A single product uses all three

Different hops, different mechanisms, one request path

Step 1 The user signs in OAuth lets them authenticate with a provider they already trust, so you never handle their password.
Step 2 Your app issues a session A JWT identifies that user on every subsequent request without a database lookup each time.
Step 3 Your backend calls out An API key authenticates your service to model providers and other third-party APIs.
Ask who is calling whom, and on whose behalf.
No user in the request means an API key. A user talking to your own app means a JWT. Your app acting on a user's behalf somewhere else means OAuth.
Almost every mismatched auth choice comes from skipping that question.
Roadmap: identify the two parties and whether a human is involved, then pick the mechanism that models that relationship.
