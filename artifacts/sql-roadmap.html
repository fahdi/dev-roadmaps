Developer Roadmap

SQL: 24 Nodes to Production

From your first SELECT to queries you would put behind a live endpoint. The order matters, because each tier only makes sense once the one before it is automatic.

Fundamentals, one table at a time Intermediate, many tables Advanced, analytics and production

Fundamentals · nodes 1 to 10

Single table, filtering and aggregation

1SELECT / FROMPick columns from a table
2WHEREFilter rows with AND, OR, NOT
3ComparisonsEquality, ranges, BETWEEN, IN
4NULL / COALESCENULL is not a value and never equals itself
5ORDER BYSort ascending or descending
6LIMIT / OFFSETTake a slice, and paginate
7DISTINCTCollapse duplicate rows
8Aliases (AS)Rename columns and tables for clarity
9AggregatesCOUNT, SUM, AVG, MIN, MAX
10GROUP BY / HAVINGAggregate per group, then filter groups

The one that trips people: WHERE filters rows before grouping, HAVING filters groups after. Putting an aggregate in WHERE is the classic first error.

Intermediate · nodes 11 to 15

Joins and reshaping across tables

11INNER JOINRows matching in both tables
12LEFT / RIGHT JOINKeep one side even without a match
13FULL / CROSS JOINKeep both sides, or produce every pairing
14SubqueriesA query used as a value, table or filter
15CASE WHENConditional logic inside the query

The one that trips people: a WHERE condition on the right-hand table quietly turns a LEFT JOIN back into an INNER JOIN. Put that condition in the ON clause instead.

Advanced · nodes 16 to 24

Analytics, readability and the parts that make it production grade

16String functionsSplit, trim, concatenate, match
17Date and timeTruncate, difference, bucket by period
18Set operationsUNION, INTERSECT, EXCEPT
19OVER / PARTITION BYAggregate without collapsing rows
20Ranking functionsROW_NUMBER, RANK, DENSE_RANK
21Offset functionsLAG, LEAD, NTILE, FIRST_VALUE
22CTEs (WITH)Name the steps, including recursive ones
23Indexes / EXPLAINRead the plan before you tune anything
24Transactions / ViewsACID guarantees and saved abstractions

Window functions are the jump. GROUP BY collapses rows to give you an aggregate; OVER gives you the aggregate alongside every row. Once that clicks, running totals, per-group ranking and period comparisons stop needing self-joins.

CTEs, indexes and transactions are where production starts.
AI will happily generate SQL for you. Reading EXPLAIN, spotting the accidental cross join and knowing what the transaction actually guarantees is how you tell whether the query it produced is right.
Generating SQL got cheap. Verifying it did not.
