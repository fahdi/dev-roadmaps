MCP vs A2A

Two protocols at two different layers of the agent stack, not two ways of doing the same thing. Step one task through both and watch where the decision actually gets made.

Task: "Book me a flight to Bali on May 20 and put it in my calendar."

MCP

Model Context Protocol

The LLM stays in control. MCP gives it tools to reach for.

A2A

Agent-to-Agent Protocol

Agents collaborate. The orchestrator delegates and never touches a tool itself.

  • LLM in control. One model reasons about the whole task.
  • Centralised tool access. Every tool arrives through one client.
  • Best for single-agent flows, where one reasoner with good tools is enough.
  • Agents in control. Each one owns its own reasoning.
  • Decentralised execution. Specialists hold their own tools and credentials.
  • Built for multi-agent systems, where the work splits across owners.
They are layers, not rivals. A2A agents very often speak MCP underneath.
MCP answers "how does a model reach a tool". A2A answers "how does an agent hand work to another agent".
Reach for A2A when the work has genuinely separate owners. Reaching for it earlier buys you a distributed system you did not need.
Roadmap: name the layer before picking the protocol, then check whether one reasoner with tools would have done it.
