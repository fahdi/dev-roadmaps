Developer Roadmap

API vs Function Calling vs MCP

MCP does not replace function calling, and function calling did not replace APIs. They are three layers of the same stack, and the confusion comes from treating them as competing options.

Three layers · not three alternatives
01

API

Since forever

Your code calls an endpoint and gets data back. No model is involved anywhere in this loop.

Your code→ API→ Data

This layer never went away. Everything above it eventually bottoms out here, which is why an API that is slow or unreliable stays slow and unreliable no matter what you wrap around it.

02

Function Calling

2023

You describe your functions with a schema. The model reads it and says which one it wants and with what arguments. Your app is what actually calls it.

Model→ Schema→ Your app→ API

The model requests, it does not execute. Every tool needs its own integration written by you, so ten tools across three apps is thirty pieces of glue.

03

MCP

2024

A standard interface between a model and a capability. Write the server once and any compatible client can use it, instead of rebuilding the same integration per app.

Model→ MCP client→ MCP server→ GitHub, database, files
Tools Resources Prompts

It exposes more than functions. Tools do things, resources supply context, prompts ship reusable instructions, and underneath it is still calling an API.

Same task, different abstraction layer

API Executes the work. Function calling Lets the model ask for a tool, in a shape your code can act on. MCP Standardises access to tools, resources and prompts, so integrations stop being per-app work.
Roadmap: the API does the work, function calling lets a model request it, MCP makes that request portable across clients.
Pairs with 6 Levels of Agentic AI, where tool calling is level 3, and Design Your Agent's Control Plane for wiring MCP servers into a project.
