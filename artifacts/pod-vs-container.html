Container

The unit of packaging

One process and everything it needs to run, built from an image. A container runtime starts it, and on its own it has its own network namespace and its own filesystem.

Kubernetes never schedules one directly. There is no such thing as deploying a bare container to a cluster; it always ends up wrapped.

Pod

The unit of scheduling

One or more containers placed on the same node, sharing an IP, a network namespace and any volumes you mount. They reach each other on localhost.

It is also the unit of scaling: a Deployment adds and removes whole pods, never individual containers inside one.

"They share a network namespace" is not trivia. It is why two containers in one pod cannot both listen on 8080.
Same IP, same port space, one lifecycle, scaled together as a block.
Put a container in a pod because it must live and die with the main one. Anything else belongs in its own pod.
