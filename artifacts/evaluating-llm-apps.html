How to Evaluate an LLM App

"It looks good to me" is not an eval. The pipeline that replaces vibes: a golden dataset, four kinds of evaluators, and a loop where every failure becomes a test case.

First, Three Different Jobs

Evals, guardrails and monitoring get used interchangeably. Conflate them and you leave an ops gap.

Before ship Evals Measure Quality and reliability, on cases you chose in advance. Asks: is it good? Miss it → bad output
During run Guardrails Enforce Policy, scope and limits, inline on the live request. Asks: is it allowed? Miss it → unsafe action
After deploy Monitoring Detect Drift, cost and latency, on real production traffic. Asks: is it healthy? Miss it → silent incident

Quality ≠ control ≠ visibility. Cover all three, or the gap is where your incidents live.

2
The Four Evaluators

Pick per check: cheap and deterministic first, expensive & human last.

Code-based Checks
Deterministic logic: schema compliance, exact matches, latency limits, tool-argument validation. Fast, reproducible, limited to the verifiable.
Ground Truth
Compare against trusted reference answers, which suit classification & extraction where a known correct state exists.
LLM-as-Judge
A model scores outputs against a written rubric: correctness, groundedness, tone. Calibrate the judge against human labels before trusting it.
Human Review
Experts on ambiguous, high-risk cases, and the calibration source for everything automated. Expensive, so spend it where it matters.

Baseline Scores

Score on six dimensions, not one number, because an average hides the one that broke.

Correctness did it get the answer right
Groundedness is every claim supported
Tool success did the calls actually work
Safety did it stay inside policy
Latency p95 the slow tail, not the mean
Cost per run what one answer costs you

Then diagnose: bucket the failures, fix the biggest bucket, rerun only the failed cases.

Rollback

A regression blocks the ship. No green run, no release. Pin the model version rather than tracking "latest", canary a slice of traffic with the abort metric picked up front, run the new version in shadow where its answers never reach a user, and keep rollback a button rather than a plan.

Don't ask "does it look good?". Ask "what's the score on the cases that used to fail?"
Vibes don't scale. Every production failure that reaches step 6 gets promoted into the golden dataset at step 1, and that loop is the whole system.
Roadmap: golden dataset → four evaluators → offline baseline → CI/CD gate → guardrails inline → online evals → failures feed back.
